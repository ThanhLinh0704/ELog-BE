assignedRoute: Join với bảng route_stops để biết store đang ở tuyến nào. Sẽ là null nếu store chưa được gắn vào bất kỳ tuyến nào. Field này sẵn sàng cho US-04 dùng ngay khi Sprint 2 build Route Management.

Business rules — PATCH /api/stores/{id}/status:

Trước khi cho phép is_active = false:

1. Kiểm tra store có đang là RouteStop của Route đang ACTIVE không
   → Nếu có: HTTP 409 · "Store đang thuộc tuyến [RT-XX]. Hãy xoá store khỏi tuyến trước."

2. Kiểm tra store có trip đang ở trạng thái Dispatched / InProgress không
   → Nếu có: HTTP 409 · "Store có [N] chuyến đang vận hành. Vui lòng đợi hoàn tất."
   [ASSUMPTION: Trip entity chưa có ở Sprint 1 — check này sẽ được bổ sung khi Trip
   được implement ở Sprint 4 (US-16). Tạm thời bỏ qua check #2, chỉ làm check #1.]

Acceptance Criteria

Tạo store mới hợp lệ → HTTP 201, isActive = true, assignedRoute = null

Tạo store với storeCode trùng → HTTP 409 với message rõ

Nhập latitude mà không có longitude (hoặc ngược lại) → HTTP 400

contactPhone sai định dạng → HTTP 400 với message hướng dẫn

Response GET /api/stores trả đúng assignedRoute (null nếu chưa gắn tuyến)

hasRoute=false chỉ trả về stores chưa thuộc tuyến nào

PATCH vô hiệu hoá store đang là RouteStop active → HTTP 409

DISPATCHER gọi POST/PUT/PATCH → HTTP 403
