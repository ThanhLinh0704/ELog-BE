US-02 Authentication & Authorization

TASK-01 Design User / Role Schema

Mô tả: Thiết kế và tạo Flyway migration cho các bảng users, roles, user_roles. Schema phải hỗ trợ đủ 5 roles trong scope (DISPATCHER, WAREHOUSE_STAFF, DRIVER, LOGISTICS_MANAGER, SYSTEM_ADMIN).

Chi tiết kỹ thuật tham khảo:

Bảng users: id, username, password_hash, full_name, email, is_active, created_at, updated_at

Bảng roles: id, name (enum), description

Bảng user_roles: user_id, role_id (many-to-many)

Seed data: ít nhất 1 tài khoản SYSTEM_ADMIN mặc định

Viết Flyway migration file V2__auth_schema.sql

Acceptance Criteria:

Migration chạy thành công, không lỗi

5 roles được seed đúng

Password field lưu hash, không lưu plaintext




TASK-02 Implement JWT Authentication

Mô tả: Implement luồng login và JWT token lifecycle trong Spring Boot. Bao gồm phát hành token, validate token, và refresh token.

Chi tiết kỹ thuật tham khảo:

Endpoint POST /api/auth/login → nhận username/password → trả access_token + refresh_token

Endpoint POST /api/auth/refresh → nhận refresh_token → trả access_token mới

Endpoint POST /api/auth/logout → invalidate refresh token

Dùng thư viện jjwt (io.jsonwebtoken)

access_token TTL: 15 phút; refresh_token TTL: 7 ngày

Lưu refresh token vào DB (bảng refresh_tokens) để hỗ trợ logout/invalidate

Payload JWT chứa: userId, username, roles, iat, exp

Cấu hình SecurityFilterChain — whitelist /api/auth/**

Acceptance Criteria:

Login đúng credentials → trả token hợp lệ

Login sai credentials → HTTP 401

Token hết hạn → HTTP 401 với message rõ ràng

Refresh token hoạt động đúng

Logout invalidate refresh token, không dùng lại được





TASK-03 Implement RBAC Authorization

Mô tả: Cấu hình Spring Security để kiểm soát quyền truy cập endpoint theo role. Định nghĩa role-permission matrix cho toàn bộ scope INC-1.

Chi tiết kỹ thuật:

Dùng @PreAuthorize("hasRole('...')") annotation trên controller methods

Định nghĩa permission matrix ban đầu (ít nhất cho các endpoint đã có ở US-01/02/03):

Trả 403 Forbidden kèm error body chuẩn khi không đủ quyền

Tạo file PERMISSION_MATRIX.md trong repo để làm tài liệu sống

Acceptance Criteria:

Đúng role → truy cập được endpoint

Sai role → HTTP 403, không lộ thông tin hệ thống

SYSTEM_ADMIN có quyền cao nhất

Driver chỉ thấy được tài nguyên của chính mình (chuẩn bị cho NFR Security)


TASK-04 Create Login UI

Mô tả: Tạo trang Login trên ReactJS, tích hợp với backend Auth API, quản lý token trong client.

Chi tiết kỹ thuật:

Route: /login (public, redirect về / nếu đã login)

Form: username, password, nút Login

Lưu access_token vào memory (Zustand/Context), refresh_token vào httpOnly cookie hoặc localStorage (team thống nhất approach)

Tạo Axios interceptor: tự động đính Authorization: Bearer <token> vào mọi request

Interceptor tự động gọi /refresh khi nhận 401, retry request gốc

Redirect sau login theo role: DISPATCHER → /dashboard, ADMIN → /admin, ...

Hiển thị lỗi rõ ràng: sai mật khẩu, tài khoản bị khóa (is_active = false)

Acceptance Criteria:

Login thành công → redirect đúng trang theo role

Login thất bại → hiển thị thông báo lỗi, không crash

Refresh token tự động — người dùng không bị đá ra giữa phiên làm việc

Giao diện responsive cơ bản
